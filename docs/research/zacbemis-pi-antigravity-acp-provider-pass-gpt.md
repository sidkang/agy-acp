## 2. What both missed — additional verified details (beyond their overlapping summaries)

- **Error mapping:** `classifyError` preserves existing typed errors; SDK/numeric structured errors with code **-32000 → auth**, every other numeric code **→ protocol**, cause retained; only string `data.details` is appended and redacted there. Nonstructured Error is returned unchanged (Z `src/acp/connection.ts:446-475`). Thus neither arbitrary message wording nor HTTP-like 429 is mapped directly to `quota`.
- **Delivery boundaries:** Pi writer redacts on failure and emits only `reason: error|aborted` plus AssistantMessage (Z `src/stream/pi-events.ts:89-100`); process exit is `process_exit` even for child spawn-error settlement (`src/acp/process.ts:168-172,238-246`; `src/acp/connection.ts:78-84`). Typed code vocabulary is not a guarantee of granular host-visible codes.
- **Quota interception detail:** metrics increment **before** the quota gate; only accumulated text blocks are matched, not thinking. Notice is anchored at start/newline and end of trimmed reply; exact wording with optional relative or UTC reset (Z `src/runtime.ts:652-660`; `src/acp/quota.ts:4-21`). `test/runtime-safety.test.ts:338-380` asserts no checkpoint progress, retained live binding, and preservation of a normal quoting reply; inspected, not run. This is checkpoint protection, not buffering/retraction of already streamed output.
- **Watchdog's two budgets:** **10 min idle / 60 min work-inactive** defaults, independently configurable and validated before spawn (Z `src/acp/connection.ts:38-46,63-70`). Busy = explicit holds OR permission count OR outstanding native-tool IDs; each session update rearms, including unknown/status-only updates; completed/failed removes native IDs (Z `src/acp/prompt-watchdog.ts:25-49`). This is inactivity, never a total-turn cap.
- **Watchdog lifecycle:** nested releases are idempotent; timer unref, single fire, dispose clears state (Z `src/acp/prompt-watchdog.ts:25-37,60-78`). Pi MCP calls hold while parked (`src/runtime.ts:917-929`); permission RPCs acquire/release around handler (`src/acp/connection.ts:100-110`). Stall rejects timeout **and closes connection/process** (`:399-419`); user abort first notifies cancel, forces close after **1.5 s** (`:291-318`). Permission UI also has its own **120 s** auto-denial budget (`src/runtime.ts:56,945-952`), not a 60-minute permission-approval allowance.
- **Store locking limits:** synchronous `proper-lockfile.lockSync`, `realpath:false`, retry via 10 ms Atomics.wait, 5 s deadline, 30 s stale threshold, finally release (Z `src/acp/store-lock.ts:6-23`). Save/remove/clear locked; reads catch corruption/I/O as empty and are unlocked; records written pid-temp + rename, directory 0700/file 0600 (Z `src/acp/session-store.ts:27-68`). This protects provider metadata, not the runtime's native conversation DB or a cross-process live-session lease.
- **Loopback auth policy:** exact case-sensitive `Bearer <dashless UUID>` compared only after equal byte lengths; no bridge-level Host/Origin check in `handle` (Z `src/mcp/bridge.ts:64,116-160,209-212`). SDK middleware behavior was not inspected. Wrong path/method gets 405 before auth, bad auth 401 before reading body; each authenticated POST owns and closes its SDK server/transport (`:116-160`). Do not describe that as equivalent to Magpie's explicit Host/Origin guards (M `src/mcp/http-server.ts:120-145`).
- **Schema policy beyond limits:** annotations may drop; unknown validation keywords reject the entire tool. Rejects proxy/accessor/custom-prototype/symbol objects, sparse/custom arrays, cycles and `__proto__` properties; small shared acyclic subschemas allowed; preserves supported combinators; adds singleton enum for const; never infers a type (Z `src/mcp/schema.ts:55-103,106-118,125-181,190-217`). Only root `type === object` accepted (`:28`). This is conservative JSON Schema projection, not proof that every preserved keyword is accepted by our `agy` translator.
- **Projection identity:** duplicates after name sanitation/truncation are omitted; omissions participate in tool fingerprint, and changed fingerprint invalidates warm binding (Z `src/mcp/bridge.ts:45-58,165-193`; `src/runtime.ts:513-517,587-595`). Unsupported HTTP MCP capability produces explicit omissions instead of advertising unusable tools (`:790-799`). Original TypeBox validation failure/exception returns MCP `isError`, never dispatches (`src/mcp/bridge.ts:137-148,215-216`).
- **Credential switches:** any nonblank `AGY_ACP_FORCE_FILE_STORAGE` is respected as an override, not parsed as a boolean. Otherwise only macOS + structurally refreshable token file + missing/locked/denied keychain lookup produces child-only `=1`; lookup is `/usr/bin/security find-generic-password -s gemini -a antigravity-acp`, no secret-output flag, stdio ignored, 3 s timeout (Z `src/acp/credential-storage.ts:8-16,39-49,61-92`). Backend description explicitly says **expected**, not a running-process observation (`:95-111`).
- **Credential-home scope:** child HOME/GEMINI_HOME controls the inspected store; API-key env can bypass OAuth-file selection, and local token health is structural, not proof of network validity (Z `src/acp/antigravity.ts:57-67,87-127,180-186`). No runtime credential backend implementation was inspected; the switch's server semantics are documented by provider comments, not verified against our CLI artifact.
- **Packaging/platform:** npm ships TS extensions/src/docs/manifest (not a runtime binary), MIT, Node **>=22.19.0**, wildcard Pi/typebox peers, exact SDK/MCP/lockfile dependencies (Z `package.json:5-6,29-43,60-73`; `LICENSE:5-13`). A separate Node executable is required even for standalone Pi; resolver honors NODE then node/nodejs/PATH (`src/acp/process.ts:43-68`).
- **Runtime ownership/platform:** six OS/arch combinations: macOS/Linux/Windows × arm64/x64; Linux installer rejects musl; native Linux launch adds `--uid=`; Windows payload uses `.exe` (Z `src/acp/setup.ts:274-277,738-760`; `src/acp/antigravity.ts:148-160`; `runtime-manifest.json:282-347`). Install root is `~/.local/opt/agy-acp`, version directories by archive hash; zip must contain exactly the two expected regular files with signed sizes; archive hash checked, extracted launch identity validated (Z `src/acp/setup.ts:294-299,324-358,388-446,625-627`).
- **Updates/trust boundary:** default automatic (Z `src/config.ts:44-58`), 24 h check cache; latest registry version must be approved in signed manifest or falls back to latest approved; matching versions require matching registry URL; manifest outage falls back cached/bundled and working managed launch survives update-resolution failure (Z `src/acp/setup.ts:26-30,176-237`). Managed integrity is installation-time archive trust plus later file metadata checks, not continuous executable attestation.

## 3. What Magpie should take — five decisions, concepts vs copyable code

1. **adopt — progress watchdog with finite busy budget.** Concept: distinguish idle generation from pending tool/permission work, then close the owned process on stall (Z `src/acp/prompt-watchdog.ts:25-49,68-78`; `src/acp/connection.ts:399-419`). Prevents healthy long turns timing out mid-progress and forgotten tool completion hanging indefinitely. M still passes absolute 30 min (`src/runtime/worker.ts:1488-1495`); its request timeout only rejects/deletes pending RPC (`src/runtime/acp-connection.ts:342-353`). **Cost:** moderate event/hold/worker-close wiring. **Code we could copy:** small watchdog state machine (adapt notification types); not the entire server connection or arbitrary 10/60 defaults.
2. **adopt — expand diagnostic redaction vocabulary, retain ours too.** Concept: sanitize at outward error boundary plus bounded stderr, covering URL userinfo, API-key prefixes, Basic/header/cookie and JSON secret keys (Z `src/acp/errors.ts:27-42`; `src/stream/pi-events.ts:89-100`). Prevents credential leakage in failures. M `src/accounts/env.ts:605-622` covers OAuth/Bearer/MCP URLs but lacks several of these forms. **Cost:** low, careful regex composition and diagnostic readability review. **Code we could copy:** selected patterns, not wholesale replacement: upstream lacks our `/mcp/<token>`/OAuth-code coverage and is not exhaustive cookie redaction.
3. **defer — fail-closed schema projection plus original-contract validation.** Concept: omission reason + fingerprint, no silently widened constraints, validate before dispatch (Z `src/mcp/bridge.ts:137-148,165-193`; `src/mcp/schema.ts:20-33,75-103`). Prevents a lossy advertised schema becoming permission to execute invalid arguments. **Cost:** moderate/high compatibility choice: M deliberately lowers refs/unions to `agy`'s narrower translator (`src/mcp/schema/sanitizer.ts:929-939`), and call dispatch currently parks object arguments (`src/mcp/broker.ts:360-390`). **Code we could copy:** omission/fingerprint and budget ideas; not TypeBox-specific `Value.Check` or the wholesale preserved-combinator schema projector. First decide validator/dialect and expected tool-loss policy; do not assume server artifacts share schema acceptance.
4. **skip for us — replace shelf locking with proper-lockfile.** Concept worth retaining: lock the entire reload/mutate/rename transaction, not only write (Z `src/acp/store-lock.ts:5-23`; `src/acp/session-store.ts:33-47,60-68`); prevents concurrent lost updates. **Cost:** unnecessary dependency and different stale-lock policy; M already does this and fails closed (`src/sessions/shelf-store.ts:320-331,551-574`), refusing to reclaim a live PID (`:247-284`). **Code we could copy:** none needed; keep the existing mechanism, reject D's stale comparison.
5. **defer — explicit credential-backend selection, not the server's switch blindly.** Concept: respect explicit override; inspect the **child's** credential home; change only child env when a known backend mismatch exists (Z `src/acp/credential-storage.ts:61-92`). Prevents repeated consent/setup failures from selecting the wrong store. **Cost:** low adapter only after backend support is proven; compatibility investigation otherwise. M currently uses isolated HOME + SSH marker (`src/accounts/env.ts:210-211,273-274`) for a different CLI/store. **Code we could copy:** decision/reason shape, not keychain coordinates/token paths or assumed `AGY_ACP_FORCE_FILE_STORAGE` support.

Copying upstream code requires retaining its MIT notice (`LICENSE:5-13`). Remaining verification gaps: actual Google artifact documentation/provenance beyond code's URL policy, opaque runtime behavior, downstream Pi handoff semantics, and whether our `agy` accepts that credential switch. None is promoted to a verified fact here; no implementation changes are proposed as completed.
