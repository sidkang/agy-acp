# pi-agy-acp (fdkevin0) — independent extraction pass

Snapshot: shallow clone of `https://github.com/fdkevin0/pi-agy-acp`, HEAD `19f4c26`, package version `0.1.3` (`package.json:3`). All line refs are to that commit, relative to repo root. Method: read-only source inspection; nothing was executed (no `npm test`, no package run, no `agy`).

## 1. Host and upstream

- A **Pi Coding Agent extension**, not a standalone server: `pi.extensions → ./index.ts` (`package.json:15-19`), peer deps `@earendil-works/pi-ai|pi-coding-agent|pi-tui` with `*` (`package.json:32-36`), dev-pinned `~1.5.0` (`package.json:41-47`). Target Pi 1.5.x, Node >= 22.19.0 (`package.json:29-30`, `docs/reference.md:165-168`).
- Registers provider id `antigravity-acp` with `api: 'antigravity-acp'`, a fake `baseUrl: 'acp://local'`, placeholder `apiKey: 'local-agy'`, and `streamSimple` as the only model entry point (`index.ts:76-83`). No HTTP endpoint is exposed to the host; the provider is a pure function call surface.
- Drives the **official `agy` CLI**: `agy acp --gemini-dir <home> --app-data-dir agy --agent pi-bridge --process-per-session --disable-telemetry --log-file <home>/acp.log` (`runtime.ts:656-669`). Binary resolution: `PI_AGY_COMMAND` (must be absolute), else `~/.local/bin/agy`, else PATH scan (`preflight.ts:85-125`). Minimum CLI 1.4.12 (`preflight.ts:29-30,133-154`).
- Protocol: **ACP v1** as newline-delimited JSON-RPC 2.0 on the child's stdio; `initialize` sends `protocolVersion: 1`, empty `clientCapabilities`, `clientInfo {name:'pi-agy-acp', version: package version}` (`acp-process.ts:189-200`, `jsonrpc.ts:1-7,186-192`).
- Authentication is **not** in-process: agy owns the OAuth session. The extension copies `~/.gemini/antigravity-cli|antigravity/antigravity-oauth-token` into the isolated home's `agy/` when the source is newer, chmod 0600 (`preflight.ts:175-213`); refresh stays agy's responsibility (`docs/reference.md:124-126`). Messages matching `/authentication required|not logged in|unauthenticated|sign in/i` map to `AUTH` telling the user to run `agy` once (`runtime.ts:1515-1525`).
- Provenance: adaptation of `dsh-llm-antigravity-acp` at snapshot `f049913`, MIT, retaining ACP runtime, JSON-RPC transport, MCP bridge, history projection, catalog, preflight and quota reader (`NOTICE:1-10`).

## 2. Transport and processes

- **One** long-lived `agy acp` front child per runtime, spawned lazily on the first request or catalog probe (`runtime.ts:313-327,648-685`); agy forks per-session workers behind that front (`acp-process.ts:1-8`). Pi-side process count per turn is therefore 1 (plus 0–1 short-lived quota process).
- One ACP session per Pi `sessionId`; cap `maxLiveSessions: 16`, evicting the oldest idle conversation first and otherwise failing fast with `RATE_LIMIT`/`CAPACITY_EXCEEDED` rather than queueing, because a waiting subagent and its parent share one provider route and would deadlock (`config.ts:56`, `runtime.ts:577-619`).
- Idle sessions close after 30 min via a 60 s sweeper; `anon-*` conversations close after every step; a failed open releases its capacity slot (`config.ts:57`, `runtime.ts:315-317,1362-1378,1477-1490`).
- Extra processes: `agy --version` (30 s) at preflight (`preflight.ts:323-336`) and `agy -p /usage --output-format json` (45 s) per quota read (`quota.ts:156-166`).
- State carrying: the ACP session owns conversation history. Reuse requires an unchanged system-prompt digest **and** the previous message-id list to be an exact prefix; otherwise the session is closed and Pi's history is replayed into a new one (`runtime.ts:1015-1079`, `history.ts:1-9`). Model/effort selection is tracked per conversation (`runtime.ts:153-157,972-996`).
- Timeouts: initialize 120 s (`runtime.ts:681`), `session/new` 120 s (`runtime.ts:814`), `session/set_config_option` 60 s (`acp-process.ts:250`), `session/close` 15 s (`acp-process.ts:288`), SIGTERM→SIGKILL escalation 5 s (`host.ts:28-36`), abort-drain wait 5 s (`runtime.ts:1233-1245`), MCP `headersTimeout` 10 s / `requestTimeout` 30 s (`mcp-bridge.ts:127-131`), SSE keepalive 15 s (`config.ts:59`), parallel-call grouping window 250 ms (`config.ts:58`).
- **`session/prompt` carries no timeout** (`acp-process.ts:261-269`): a stalled turn has no adapter-side watchdog. Stall cover is indirect only — SSE keepalives/progress on parked tool calls (`mcp-bridge.ts:367-392`) and agy's own notices.
- **Retry policy: absent.** No backoff, no re-request, no respawn loop. On child exit the runtime records `state: 'error'` and fails in-flight turns with `TRANSPORT` (`runtime.ts:727-745`); the next request restarts from scratch. Recovery levers are Pi-side: up to 3 automatic long-decode continuations on `max_tokens` (`config.ts:61`, `conversation.ts:544-557`, `runtime.ts:1188-1193`), and dropping agy's internal `⚠ API error (attempt N)` notices while counting them (`conversation.ts:26-27,269-282`).
- The isolated `--gemini-dir` home carries the `pi-bridge` agent definition and an agy `settings.json` with `toolPermission: 'request-review'`, `agentMode: ''`; startup deletes prior conversation DBs/brain artifacts and rotated `acp.log.N` (`preflight.ts:216-253,261-315`). Concurrent Pi instances therefore need distinct `PI_AGY_HOME`, since cleanup assumes exclusive use (`docs/reference.md:113-122`).
- Only `session/update` notifications are routed, keyed by session id; consumed sub-kinds are `agent_message_chunk`, `agent_thought_chunk`, `tool_call`/`tool_call_update` and `config_option_update` (`acp-process.ts:317-322`, `conversation.ts:251-263,701-710`, `runtime.ts:790-809`).
- Robustness on the wire: malformed frames are dropped without killing the link (`jsonrpc.ts:205-220`), unknown `session/update` notifications are ignored (`acp-process.ts:317-322`), disposal is idempotent with owner/epoch guards on every async callback (`runtime.ts:392-436`).

## 3. Tool channel

- Pi tools reach agy through a **loopback Streamable-HTTP MCP server** bound to an ephemeral `127.0.0.1` port, path `/mcp/<tenantKey>`; MCP protocol string `2025-06-18`; the tenant-less root returns 401; non-POST is 405 with `allow: POST, DELETE` (`mcp-bridge.ts:93,96-166,220-241`). Body cap 1 MiB, including chunked uploads (`mcp-bridge.ts:91,450-462`).
- The tool inventory is taken from Pi's live step state, `getCurrentTools(context.messages)`, so the advertised set can change between steps; changes are reconciled each request (`pi-stream.ts:132-136`, `mcp-bridge.ts:484-523`).
- Registration is per `session/new`: `mcpServers[0] = {type:'http', name:'pi', url, headers:[{Authorization: 'Bearer <secret>'}]}` (`runtime.ts:765-775`). Credentials are per session — 16-byte hex tenant key plus 24-byte hex secret, compared with `timingSafeEqual` after a length guard (`runtime.ts:763-764,844-859`).
- **Bridge lifetime = ACP session lifetime**: the tenant registers in `openSession`, and `releaseTenant` (called from `clearSession`) deletes it and forgets its MCP handshake evidence (`runtime.ts:862-866,1113-1123`; `mcp-bridge.ts:188-195`). The HTTP listener itself lives for the runtime and closes in `dispose` (`runtime.ts:408-415`).
- Call path: `tools/list` returns session tools plus `pi_call_tool` and `pi_await_result` (`runtime.ts:1380-1385`); `tools/call` passes a permission gate, then parks (`runtime.ts:868-950,1387-1439`). Agent-visible names are `mcp_pi_<name>`; the adapter synthesizes its own ids `agy_<turnTag>_<n>` rather than trusting agent ids (`history.ts:17-22`, `conversation.ts:174-195`).
- Reaching the host: a parked call is emitted as `block-start` / `tool-call-delta` / `block-end` plus `finish(tool-calls)` for that Pi step (`conversation.ts:502-543`). Pi runs the tool through its own permission/execution pipeline and returns results on the next request, which resolves the deferred and resumes the **same** ACP turn; if the agent ended its prompt meanwhile, a continuation prompt is sent with the results as transcript text (`runtime.ts:1250-1309`).
- Results return as an MCP SSE frame (`event: message` / `data: {jsonrpc,id,result}`); headers are flushed immediately because the agent reportedly abandons after 60 s without headers, with keepalive comments and `notifications/progress` while parked (`mcp-bridge.ts:344-355,367-392,417-426`). Tool results are normalised to text+image items, `(no output)` when empty (`runtime.ts:1316-1338`).
- Long tools: after 85 s the parked MCP call answers with a "still running, call `mcp_pi_pi_await_result` with this call_id" notice (`config.ts:60`, `runtime.ts:1441-1475`, `conversation.ts:639-648`); text/thought emitted meanwhile is buffered up to 64 KiB (`conversation.ts:137,227-245`).
- Hardening: permission decisions use only agent-reported structured metadata (`mcpServerName`/`mcpToolName`/`_meta`), never `title`/`rawInput`; contradictory repeats are refused; identity-less probes need a completed MCP handshake and never get `allow_always` (`runtime.ts:868-950`, `conversation.ts:669-735,737-744`). Non-permission agent→client requests are refused `-32601` (`acp-process.ts:324-338`); `resources`/`prompts` list empty (`mcp-bridge.ts:310-315`). Oversized schemas are compacted under 1350 B with full prose moved to the system prompt (`mcp-bridge.ts:525-587`), and tool changes are pushed as `<harness_tool_update>` deltas (`mcp-bridge.ts:484-523`).

## 4. Thinking/reasoning surface

- `session/update.agent_thought_chunk` → internal `thought` event → Pi `thinking` block with `thinking_start`/`thinking_delta`/`thinking_end` and `partial` snapshots (`conversation.ts:258-263,495-497`; `pi-stream.ts:224-247,287-291`).
- Shape is `{type:'thinking', thinking: string}` only. **No signature exists anywhere in `src/`** (zero matches for `signature`), no redaction handle, no provider attestation. Reasoning arrives and is re-emitted as plain text.
- Historical reasoning is **not** replayed: `renderTranscript` drops `reasoning` and `tool-call` blocks from assistant text and re-adds only tool calls (`history.ts:139-153`); when Pi history is resent into a live session, thinking becomes `{type:'reasoning', text}` (`pi-stream.ts:52-53`) — for live-session increments, not for the `<pi_history>` transcript.
- Host declarations: `reasoning: efforts.length > 0`, `thinkingLevelMap` with `off/minimal/xhigh/max` all `null` (`index.ts:57-69`); request mapping `minimal→low`, `xhigh→high`, `max→high`, `off→undefined` (`pi-stream.ts:139-147`); default effort `high` (`config.ts:55`), clamped to the nearest offered effort (`catalog.ts:53-65`, `runtime.ts:229-233`); `thought_level` is written only for families with selectable efforts, since fixed variants reject it (`runtime.ts:982-996`).
- Token accounting: `thoughtTokens` clamped to `outputTokens` (`conversation.ts:387-390`); input/cache buckets divided by model-call count for multi-step turns — explicitly an approximation (`conversation.ts:358-403`). Usage exists only on the `session/prompt` result, so parked steps report nothing separately (`docs/reference.md:149-154`).

## 5. Errors

- One regex ladder in `mapError` (`runtime.ts:1506-1541`): `JsonRpcClosedError`→`TRANSPORT`; `/authentication required|not logged in|unauthenticated|sign in/`→`AUTH`; `/timeout|timed out|deadline/`→`TIMEOUT`; context-window patterns→`CONTEXT_WINDOW_EXCEEDED`; `/rate.?limit|429|too many requests|overloaded|capacity/`→`RATE_LIMIT`; `/quota|resource.?exhausted|limit reached|exceeded your/`→`QUOTA`; else `JsonRpcRemoteError`→`SERVER`; fallback `TRANSPORT`. Ordering matters: message text is tested **before** the remote-error branch, so an ACP error whose text matches is reclassified away from `SERVER`.
- Host-visible surface is Pi's stream `error` event carrying `errorMessage`; two literal markers are injected so Pi's own classifiers fire — `context_length_exceeded: …` and `quota exceeded: …` (`pi-stream.ts:84-99,296-324`). Tests assert `isContextOverflow()` true and `isRetryableAssistantError()` false for the quota case (`tests/pi-stream.test.mjs:270-303`).
- Stop-reason mapping (`conversation.ts:544-623`): `end_turn`→`stop`, `max_tokens`→`length` (after continuations), `cancelled`→`aborted`, `refusal`→`REFUSAL`, anything else→`PROVIDER_ERROR`; `end_turn` with no visible output throws `EMPTY_RESPONSE`; ending while relayed results are unretrieved throws `PROVIDER_ERROR`.
- Codes the adapter can emit: `TRANSPORT`, `AUTH`, `TIMEOUT`, `CONTEXT_WINDOW_EXCEEDED`, `RATE_LIMIT` (including `CAPACITY_EXCEEDED`), `QUOTA`, `SERVER`, `ABORTED`, `REFUSAL`, `EMPTY_RESPONSE`, `PROVIDER_ERROR`, `UNKNOWN_MODEL` and `INVALID_PAYLOAD` (`runtime.ts:607-611,967-970,1506-1541`; `conversation.ts:569-620`; `pi-stream.ts:159-185`).
- Process death surfaces as `agy acp exited (code=… signal=…): <last 5 stderr lines>`, stderr tail retained to 64 KiB (`acp-process.ts:181-188`, `host.ts:10-13`).
- **No retry hints.** ACP carries no HTTP status/headers; a synthetic `{status:200, headers:{}}` is reported before the first event (`pi-stream.ts:203-207`). `JsonRpcRemoteError.rpc.data` is preserved but never mapped to delay/retry metadata (`jsonrpc.ts:251-259`). Permission refusals are logged and answered `reject_once`/`cancelled`; they never become turn errors (`runtime.ts:884-889`).

## 6. Prompt handling

- System prompt: `options.system` plus leading system messages are joined (`history.ts:60-74`) and shipped as `session/new` `_meta.antigravity.systemPrompt.append` behind a bridge preamble and `<harness_tool_instructions>` block (`runtime.ts:781-787`, `history.ts:96-125`). The bridged agy agent declares `tools: []`, `excludeDefaultComponents: true`, `mainAgent: true` so built-ins are removed (`preflight.ts:265-284`). Mid-conversation system messages travel in-band as `<system_update>` (`history.ts:160-163`, `runtime.ts:1069-1072`).
- History: replayed only on rebuild, newest-first into a **160,000-byte** budget chosen to stay under an alleged `64,000 × 3 = 192,000` byte `USER_INPUT` truncation; an omitted prefix is announced with a 128-byte reserve; an oversized newest tool result is head-truncated with a marker; empty trailing input becomes "Continue the task from the latest tool results above." (`history.ts:24-34,41-42,226-337`).
- Non-user input (system notices, reused tool results) is rendered as transcript blocks; an empty prompt falls back to `Continue.` (`history.ts:344-357`).
- `onPayload` may replace model/messages/tools before dispatch but harness-owned `sessionId`/`signal` are re-imposed and the replacement is shape-validated (`INVALID_PAYLOAD`) (`pi-stream.ts:149-195`).
- Compaction: none in the adapter. Pi-side compaction/tree events close conversation sessions but keep the process (`index.ts:127-132`, `runtime.ts:371-389`); a rewritten prefix forces a rebuild (`runtime.ts:486-497,1041-1051`). Automatic prompt-cache warming is vetoed (`index.ts:139`).
- Images: live user images pass through as ACP `image` blocks (`data` + `mimeType`) (`history.ts:194-209`); historical images degrade to literal `[image]` text in transcripts (`history.ts:172-187`). Models declare `input: ['text','image']` (`index.ts:56`).
- Limits: `maxTokens: 65536` hardcoded, not derived from model or ACP (`index.ts:72`); declared context 256,000 (131,072 for gpt-oss) (`preflight.ts:32-34`, `runtime.ts:216-220`). Sampling parameters, output limits, forced `toolChoice` and provider-scoped env overrides are deliberately not mapped (`docs/reference.md:170-172`).

## 7. Accounts/quota/models

- Account email is scraped from the tail (last 64 KiB) of agy logs using `applyAuthResult: email=` / `OAuth: authenticated successfully as` (`quota.ts:19-40`); the default home also reads `~/.gemini/antigravity-cli/cli.log` (`runtime.ts:269-279`). Plan/tier comes from `session/new` `_meta.antigravity.tier`, persisted in `catalog.json` (`catalog.ts:91-94,131-141`).
- Quota is read by shelling out to `agy -p /usage --output-format json` — no model prompt — parsing `command.data.groups[].buckets[].remaining_fraction`/`reset_time`; 120 s TTL applies to failures too, in-flight reads coalesce, and stale groups are retained on error (`quota.ts:143-187`, `config.ts:62`). Warnings fire at 20% and 5% remaining, deduped by group+bucket+reset+threshold (`index.ts:167-181`, `docs/reference.md:56-64`).
- Models are discovered from the `model` select config option plus `models.availableModels`; per-family efforts are derived from `${id}-${effort}` entries, with an empty set marking a fixed-variant id such as `gpt-oss-120b-medium` (`catalog.ts:131-207,118-121`). Five fallback families ship in code (`catalog.ts:27-33`); the list is disk-cached and loading never starts agy (`index.ts:84-97`).
- Preferences live in `<home>/settings.json` (`quotaDisplay`) and `<home>/catalog.json` (models, efforts, tier), both written atomically/best-effort; `PI_AGY_QUOTA_DISPLAY` overrides the display mode at startup only (`config.ts:92-125`, `catalog.ts:209-227`, `index.ts:46-49`).
- **Single signed-in account.** No multi-account registry, rotation, switching or per-account routing; identity is whatever agy holds on disk. Prices default to zero with Pi overrides honoured through `calculateCost` (`index.ts:70`, `pi-stream.ts:220`). `/agy-acp [status|quota [used|remaining]|reset]` is the only operator surface (`index.ts:187-266`).

## 8. Five bullets

1. **Copy:** per-session bearer + tenant path on the loopback MCP endpoint with constant-time compare, and permission grants bound to agent-reported structured metadata (never `title`/`rawInput`) with conflict tracking — a materially stronger spoofing posture than a shared, unauthenticated endpoint (`runtime.ts:763-764,844-950`; `conversation.ts:669-735`).
2. **Copy:** the park/relay design — end the Pi step with `finish(tool-calls)`, keep the same ACP turn alive, and answer a slow tool with an explicit "still running, call `pi_await_result`" notice instead of blocking past the agent's MCP deadline; flush SSE headers immediately to survive header deadlines (`conversation.ts:502-543,639-648`, `runtime.ts:1441-1475`, `mcp-bridge.ts:344-355`).
3. **Copy:** history-prefix reuse keyed on a system digest + message-id prefix with a byte-budgeted newest-first replay that announces omissions (`runtime.ts:1015-1079`, `history.ts:226-337`), and the two error markers that let Pi's own overflow/retry classifiers work rather than inventing new codes (`pi-stream.ts:84-99`).
4. **Avoid:** no timeout on `session/prompt` and no turn watchdog (`acp-process.ts:261-269`), so a silent agy stall is recoverable only by user abort or process death; no adapter retry/backoff; and `mapError`'s regex ladder can reclassify structured remote errors by message text (`runtime.ts:1506-1541`). Hardcoded `maxTokens: 65536` (`index.ts:72`) and input-bucket division by step count (`conversation.ts:371-403`) are lossy stopgaps.
5. **Unverifiable from code alone:** every agy behaviour the design leans on is asserted only in comments or a scripted fake — the 60 s MCP header deadline (`mcp-bridge.ts:8-9`), the 180 s MCP call deadline (`config.ts:42`), the ~1,500 B lazy tool-schema cutoff (`mcp-bridge.ts:525`), the 192,000-byte `USER_INPUT` truncation (`history.ts:25-28`), the `⚠ API error (attempt N)` and output-cap notice texts (`conversation.ts:26-33`), the `thought_level`/`availableModels` shapes and stop-reason vocabulary (`tests/fake-agy.mjs:45-79,410-435`), and the 1.4.12 minimum (`preflight.ts:29-30`). Tests exercise a scripted fake `agy` only (`docs/development.md:101-107`), so none of these were confirmed against the real binary in this pass.
