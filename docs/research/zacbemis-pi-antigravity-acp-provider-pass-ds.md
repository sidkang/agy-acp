## 2. Transport and processes

- NDJSON over stdio through a **custom bounded adapter**: 32 MiB default frame cap; one exact Chromium line (`"Opening in existing browser session."`) is tolerated and counted, anything else malformed hard-fails the transport (`src/acp/bounded-stream.ts:3,17-24,136-141`). Client capabilities advertise **no fs and no terminal** (`src/acp/connection.ts:122-137`).
- Process count per session: **2 OS processes minimum** — `node supervisor.mjs --command <agy_acp_server.par>` (`src/acp/process.ts:139-145`) wrapping the agent, detached into its own group, parent-death poll every 500 ms, TERM→KILL at 750 ms (`src/acp/supervisor.mjs:20-50,68-86`); Node side signals the group then SIGKILLs after 1500 ms, `taskkill /T` on Windows (`src/acp/process.ts:206-236`).
- Extra process pairs per ephemeral operation: model discovery, `/usage`, login, install validation — each `createConnection` is a fresh process (`src/runtime.ts:207,257-266,295-298,359,1016-1022`). The MCP bridge is an in-process HTTP server, not a process (`src/mcp/bridge.ts:81-91`).
- Wire state: `initialize` (protocol 1 + clientInfo), `authenticate`, `session/new|load|resume` (with `cwd` + `mcpServers`), `session/set_config_option`, `set_mode`, legacy `session/set_model`, `session/prompt`, `session/cancel` notify (`src/acp/connection.ts:170-275,322-324`).
- Local state: the `Binding` (writer, instruction/history fingerprints, pending permission and tools, `contextUsed`, `inferences`) (`src/runtime.ts:76-105`), plus a persisted record keyed by Pi session id (`acpSessionId`/`modelId`/`cwd`/`messageCount`/fingerprints), capped at 256 records and 30 days (`src/acp/session-store.ts:6-22`); turns per key are serialized through a promise queue (`src/runtime.ts:573-577`).
- Timeouts: operation 120 s, `initialize` 30 s, `authenticate` 180 s (10 min under the headless relay), prompt idle **10 min** / work idle **60 min**, permission 120 s, tool-batch flush 100 ms, quota prompt 30 s, install 45 min, validation 90 s (`src/acp/connection.ts:31,66-67,135,161`; `src/runtime.ts:56-59`; `src/acp/setup.ts:28-29`).
- Watchdog is **progress-based, not duration-based**: any `tool_call` pending/in_progress, or a parked Pi tool or permission, switches to the 60-min window; a stall rejects with `timeout` and closes the connection (`src/acp/prompt-watchdog.ts:5-50,52-58`; `src/acp/connection.ts:399-421`).
- Retry policy: **absent** — no backoff, reconnect or re-prompt anywhere (`retry|backoff|reconnect` appears in `src/` only as two "retry the turn" messages, `src/runtime.ts:628,840`). Recovery is structural: a dead process closes the binding and the *next* turn rebuilds resume→load→new (`src/runtime.ts:873-882,806-826`). Concurrent installs dedupe on one in-flight promise (`src/acp/setup.ts:118-123`).
- Abort semantics: abort sends `session/cancel` as a notification, then hard-closes the connection after 1500 ms and rejects as `aborted`; the writer reports `stopReason: "aborted"` rather than an error (`src/acp/connection.ts:291-320`; `src/runtime.ts:704-728`).
- Frame limits are the only size bound on the wire: outbound frames over the 32 MiB cap throw, and inbound over-long lines without a newline fail the transport (`src/acp/bounded-stream.ts:39-49,78-81`). stderr is retained as a redacted 16 KiB tail, shown only by `doctor --verbose` (`src/acp/process.ts:11,165-167`; `src/runtime.ts:437`).

## 3. Tool channel

- Model tool calls arrive as ACP `tool_call`/`tool_call_update` notifications — i.e. **Antigravity-executed native tools** — and are mapped into Pi `thinking` text (`src/acp/events.ts:22-36`; `src/runtime.ts:974-977`). Pi's own tools never reach the model through that path.
- Pi tools are exposed by a loopback MCP server that keeps the *projected* schema for advertisement and the *original* Pi schema for call-time revalidation (`src/mcp/bridge.ts:21-27,137-148`); names are `pi_<name>` sanitized to `[a-zA-Z0-9_-]{1,64}` with a **hard cap of 64 tools** (`src/mcp/bridge.ts:19,174-178`).
- Descriptor given to the agent: `{type:"http", name:"pi-bridge", url:"http://127.0.0.1:<ephemeral>/mcp", headers:[{Authorization:"Bearer <token>"}]}`; token is a dashless UUID minted per bridge (`src/mcp/bridge.ts:64,106-114`). Only `POST /mcp`; Bearer compared with `timingSafeEqual` on equal-length buffers else 401; body ≤1 MiB; `maxConnections = 8`; a fresh stateless MCP `Server` per request (`src/mcp/bridge.ts:81-84,116-162,197-213`). Started only when the agent advertises `mcpCapabilities.http` (`src/runtime.ts:790-800`).
- Results return **in-process**, never through `session/prompt`: `onCall` → `runtime.requestPiTool` → `writer.toolCall(...)` plus a 100 ms debounce before `done("toolUse")`; the ACP prompt stays parked, the watchdog is held, and the Pi `toolResult` on the next `stream()` call resolves the `CallToolResult` (`src/runtime.ts:907-936,550-570,1189-1198`). The Pi-visible tool-call id is a fresh bridge UUID, **not** the ACP `toolCallId` (`src/mcp/bridge.ts:148`).
- An unprojectable schema means **the whole tool is dropped, never widened**: seven typed reasons (`unsupported_keyword|invalid_keyword_value|unsafe_property_name|too_deep|cyclic_schema|not_object|too_large`), only annotations removable, unknown validation keywords reject the tool, proxy/accessor/symbol inputs rejected, 64 KiB + 100k-work budgets, depth 16, `__proto__` rejected, `const` mirrored into `enum` (`src/mcp/schema.ts:9-16,22-34,76-87,154,202,210-217`). Omissions surface by name and reason in `doctor`/`status` (`src/runtime.ts:136,864`; `extensions/index.ts:228`).
- Permission requests bypass the MCP bridge: synthesized as a real Pi tool `antigravity_acp_permission` whose result carries `details.kind = "pi-antigravity-acp-permission-v1"`; a missing, malformed or disabled result is an **immediate deny**, never implicit approval and never a hang (`src/runtime.ts:938-963,1094-1121`; `extensions/index.ts:75-111`).
- Late or out-of-band calls are refused as tool errors rather than dropped: a call arriving with no live writer, an open permission, or an aborted turn returns `isError` text `"Pi cannot accept this tool call in the current turn"` (`src/runtime.ts:911-916`).

## 4. Thinking / reasoning surface

- Pi is told: `reasoning: true` with a `thinkingLevelMap` of exact ACP ids, `off|minimal|xhigh|max` = `null` (`src/models.ts:132-147`). Pi effort clamps to the nearest advertised tier (`src/models.ts:107-130`); the id is then **split** into `model` + `thought_level` selectors and both must confirm or the turn fails (`src/acp/connection.ts:228-260`).
- Streaming: `agent_thought_chunk` text → Pi `thinking_start/thinking_delta/thinking_end`; ACP `tool_call` and `plan` entries are *rendered as thinking text*; usage arrives as `usage_update.used > 0` (`src/acp/events.ts:11-46`; `src/stream/pi-events.ts:49-56`; `src/runtime.ts:974-982`). Non-text thought content is deliberately dropped (`src/acp/events.ts:18-21`).
- **No signature exists.** Thinking blocks are `{type:"thinking", thinking}` only — no `signature`, no redacted payload, no provider metadata (the only `signature` in `src/` is the manifest's). Reasoning tokens surface solely as `usage.reasoning` from `thoughtTokens`, folded into `output` (`src/stream/pi-events.ts:49-56`; `src/stream/usage.ts:24-27`).
- Thought and tool-update text is sanitized before it reaches Pi: C0/C1 control bytes stripped, 2,000-char per-field clamp, at most 8 content items and 4,000 chars per tool update (`src/acp/events.ts:49-70`).

## 5. Errors

- Classifier codes: `aborted|auth|model|protocol|quota|spawn|timeout|process_exit|invalid_input` (`src/acp/errors.ts:1-21`). JSON-RPC `-32000` ⇒ `auth`; any other numeric code ⇒ `protocol` with the code embedded and `data.details` appended redacted; operations are raced against transport-failure and process-exit promises (`src/acp/connection.ts:446-476,399-421`).
- Host-visible shape: **the code is not transmitted**. Pi gets `stopReason: "error" | "aborted"` and `errorMessage = redact(message)`; `rawStopReason` carries only the ACP stop reason (`src/stream/pi-events.ts:89-101`; `src/runtime.ts:672`). No retry hint, no `retryAfter`, no structured payload reaches Pi. Redaction covers URL userinfo, `AIza/sk-/npm_/gh*_` keys, `ya29./1//` tokens, auth/cookie headers, `*_token`/`api_key` pairs, then truncates to 4 KiB (`src/acp/errors.ts:32-42`).
- Quota interception is **inside the provider, after a successful prompt**: agy answers exhaustion as an ordinary reply, so it is recognized only when `usage.totalTokens === 0 || stopReason === "refusal"`, then string-matched against one exact English notice (`"Usage Limit Reached\n\nYou have reached your current quota for this period."` plus an optional reset sentence) (`src/runtime.ts:654-661`; `src/acp/quota.ts:3-22`). Reset parses from relative `N day/hour/…` or `Mon D, YYYY HH:MM UTC` (`src/acp/quota.ts:1-21`).
- Failure mode of that design: a paraphrase, a locale change, or any non-zero token count turns exhaustion into a normal empty answer, and the notice text itself is never forwarded to Pi.
- Other invariants surface as errors: image without advertised capability (`src/runtime.ts:1052-1055`), >256 KiB instructions (`src/stream/context.ts:20-26`), no user message (`src/stream/context.ts:47,92`), mode drift mid-turn or an external `config_option_update`/`current_mode_update` (`src/runtime.ts:626-629,965-972`), unconfirmed model or mode selection (`src/acp/connection.ts:346`; `src/runtime.ts:834-836`).
- Usage accounting caveat, documented in-code: agy double-counts cache reads into `usage_update.used`, so Pi's `totalTokens` is corrected only when exactly one inference ran; multi-inference turns overcount by the last inference's cached tokens (`src/runtime.ts:662-671`; `src/acp/events.ts:41-43`).

## 6. Prompt handling

- Instructions: never truncated — a `>256 KiB` system prompt throws `invalid_input` telling the user to reduce them (`src/stream/context.ts:7,19-26`).
- History is **replayed as a bounded synthetic transcript**, not native turns. Fresh session ⇒ one `resource` block (`urn:pi:antigravity-acp:context/<uuid>`, `text/markdown`) holding `# Pi session instructions` plus `# Prior conversation`: labeled entries, explicit untrusted-data heading, fence length derived from the body, **32,000-char** budget, active tool identities pinned, tool results allocated before call arguments, oldest entries dropped first (`src/stream/context.ts:9-16,63-73,107-167,176-185`).
- Warm session ⇒ only a delta resource for unseen messages plus `WARM_CONTINUATION`/`CONTINUATION_LABEL` text; the current user turn is resent verbatim, never only as truncatable history (`src/stream/context.ts:15-16,70-91`).
- Compaction: **absent** — no provider-side summarization. The only rewind handling is dropping the binding when `messages.length < binding.messageCount` or a prefix fingerprint mismatches (`src/runtime.ts:586-596`); an instruction change also forces a rebuild because ACP has no system-update RPC (`src/runtime.ts:1002-1009,181-190`).
- Images: forwarded only from the **current user message**; history images become `"[image omitted]"` (`src/stream/context.ts:84-91,245-248`), capability-gated at send time, and `resource` blocks degrade to text when `embeddedContext` is false (`src/runtime.ts:1049-1064`). Mismatch: every model declares `input: ["text","image"]` unconditionally (`src/models.ts:167`) while the send path can throw.

## 7. Accounts / quota / models

- Accounts: one at a time. Logout deletes `acp_token.json` and strips `settings.auth` via 0600 temp+rename (`src/acp/antigravity.ts:132-146`); Pi's own marker must be cleared by `/logout` (`extensions/index.ts:148-155`). Local health is structural (`api-key-env|oauth-refreshable|configured-not-authenticated|corrupt|missing`) with a separate network probe (`src/acp/antigravity.ts:43-123`; `src/runtime.ts:372-380`).
- Quota: a **separate throwaway ACP process** sends the literal text `/usage` (no model turn) and parses the `### Quota Limits` markdown into groups and buckets (`weekly`, `5h`, else the server label), 1 % precision, ISO resets; 60 s cache with in-flight dedupe that isolates each caller's abort; the temporary conversation files are deleted once the process is gone (`src/runtime.ts:222-282`; `src/acp/usage-quota.ts:10-42`). Re-broadcast on `antigravity-acp:quota:request` with an exactly-once reply (`src/constants.ts:11`; `extensions/index.ts:43-73`).
- Models: discovery = `session/new` then read config selectors or legacy `models` (`src/runtime.ts:200-219`; `src/acp/session-state.ts:81-124`). Effort-qualified ids collapse to one Pi entry when ≥2 tiers exist; single-tier models keep their exact id (`src/models.ts:46-92`). Hardcoded offline fallback catalog with `contextWindow: 1_000_000`, `maxTokens: 65_536`, `cost` all zero (`src/models.ts:16-41,153-172`). Refresh is network-only and silent on failure (`src/provider.ts:107-129`).
- Metrics: per-process totals (turns/input/output/reasoning/cache) plus a `latestQuota` scraped from `_meta.quota` variants (`remainingRequests|remainingQueries|remaining`, `requestLimit|queryLimit|limit`, `resetTimestamp|resetAt|reset_time`, `tier|plan`) — i.e. best-effort field guessing (`src/status.ts:50-69`).
- Stale constant: `ANTIGRAVITY_ACP_VERSION = "1.1.1"` versus manifest `1.4.0` (`src/constants.ts:4`); it is unused outside `constants.ts`.
- A model switch is all-or-nothing: because the base model can change before the effort selector fails, any failure after a partial apply invalidates the binding *and* its saved session instead of reporting success (`src/runtime.ts:598-607`; `src/acp/connection.ts:236-247`). Session restore additionally requires an identical `cwd` (`src/runtime.ts:806`).

## 8. Five bullets

- **Copy:** the omission contract for tools — typed refusal reasons, whole-tool drop instead of schema widening, original-schema revalidation at call time, omissions reported by name+reason (`src/mcp/schema.ts:20-34`; `src/mcp/bridge.ts:137-148,165-195`) — plus the progress-based watchdog with a distinct long "work" window rather than one absolute turn deadline (`src/acp/prompt-watchdog.ts:5-50`).
- **Copy:** completion-confirmation discipline — every selector write is read back and a partial application is a hard error (`src/acp/connection.ts:228-260,349-369`), and requested-vs-server-confirmed permission mode is re-checked before each prompt, invalidating the binding on drift (`src/runtime.ts:514-518,626-629`).
- **Avoid:** quota detection by one exact English sentence plus a zero token count (`src/acp/quota.ts:4-9`; `src/runtime.ts:655-657`), which silently degrades to "normal empty answer" on any wording change; and advertising `input: ["text","image"]` unconditionally (`src/models.ts:167`) while the send path rejects images (`src/runtime.ts:1052-1055`).
- **Avoid:** losing error semantics at the Pi boundary — nine internal codes collapse to a redacted string with no retry hint (`src/stream/pi-events.ts:89-101`) and the blanket 4 KiB slice makes long ACP diagnostics unreadable (`src/acp/errors.ts:42`); also note the bridge minting its own tool-call UUID instead of carrying the ACP id (`src/mcp/bridge.ts:148`), which severs ACP-side correlation.
- **Unverifiable from the code alone:** (a) whether real `agy` implements `session/resume` versus `session/load` — both are attempted speculatively (`src/runtime.ts:806-826`); (b) the actual `/usage` and "Usage Limit Reached" wordings (`src/acp/usage-quota.ts:14-16`; `src/acp/quota.ts:4-9`); (c) whether the agent really calls the loopback bridge and honors the Bearer header — the repo's own `docs/IMPLEMENTATION-STATUS.md:28` records live qualification only on server 1.1.1 while the pinned catalog is 1.4.0 (`runtime-manifest.json:6`); (d) the real model/effort inventory and plan eligibility (`src/models.ts:16-41`); (e) whether the unsigned thought stream carries withheld reasoning the provider drops (`src/acp/events.ts:18-21`).
